# Native state boundary

`craft-platform` is a leaf crate for native private-path operations. Its default lint denies unsafe code; only private Windows/Unix modules permit the necessary FFI. Core, runtime, providers and CLI continue to forbid unsafe code. These scoped exceptions cover APIs without equivalent safe standard-library operations, rather than relaxing the workspace default.

The Windows wrapper owns process-token handles through `OwnedHandle`, uses aligned bounded buffers for `TOKEN_USER`, and frees OS-allocated SID/security-descriptor buffers with `LocalFree`. Native output pointers stay inside the FFI module. Calls to create directories/files receive live NUL-terminated buffers and security attributes whose descriptor remains allocated for the call. `GetSecurityInfo` allocations remain alive while owner/ACE SIDs are inspected. Open file/directory handles are retained to prevent replacement of checked Windows path components.

The public API returns ordinary Rust guards and I/O errors. It accepts no raw handle or pointer from a caller. Paths must be absolute local paths with no traversal/reparse components. New state entries get private permissions at creation; existing entries are verified rather than silently changed. The root guard pins the path chain while runtime uses SQLite's path API. No secret or token handle is serialized or logged.

Artifact support adds existing-only private reads and create-new staging. Native publication passes live NUL-terminated path buffers to Windows `MoveFileExW` without replacement/copy flags, Linux `renameat2(RENAME_NOREPLACE)` or macOS `renamex_np(RENAME_EXCL)`. Atomic replacement is never approximated with a check followed by ordinary rename. Windows no-replacement behavior, checked file reads and junction/hard-link refusal pass native tests. The Unix wrappers have source inspection only and still require native compilation/execution. [Artifact evidence](evidence/artifact-store.md) records the exact scope.

Qualification must cover native private ACL round trips, foreign/insecure ACL refusal, reparse and root replacement boundaries, file ownership/link checks, restart/concurrency and cleanup. Linux/macOS qualification is separate. A private directory is not a security boundary against malicious same-principal build code or an OS administrator; credential principals still require isolation from untrusted workloads.

The Windows profile foundation now passes private create/reopen, insecure/traversal refusal, pinned-root rename refusal, hard-link refusal and junction-root/ancestor refusal with native file access. SQLite restart, concurrent create, rollback and bounded lock waits also pass. The fixed database and persistent rollback journal stay pinned until SQLite closes; WAL/shared-memory files are refused. These results qualify local non-secret metadata on this host, not native vaults or credential-principal isolation. See [observed evidence and remaining gaps](evidence/profiles.md).

The existing process-principal lookup is now exposed through a safe metadata-only helper. Runtime's Windows credential item adapter uses the pinned native keyring crate without adding unsafe code to runtime/core or broadening the platform module's exception. A separate real-vault sentinel test passes for local persistence, fresh-process binary read, size limits, session-only refusal and cleanup. This does not qualify credential-principal isolation, generation activation, service/container contexts or multi-platform vaults. See [native item evidence](evidence/native-vault.md).
