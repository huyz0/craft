# Reviewed ticket execution boundaries

This is partial implementation of ticket application, not a public `plan tickets-create` command. The batch controller, durable run/task/link mappings, result-page publication and resume remain unfinished. General cloud commands remain available as described in the [quickstart](../cloud-quickstart.md).

The create host now accepts an additional equality constraint for the approved native payload and material metadata digest. It still requires ordinary create policy, verified grant/actor, current native metadata, original frozen freshness and an exact durable send claim. Constraints are compared before claim and in claimed-send preflight. Shared capture in `crates/craft-cli/src/issue_create/material.rs` keeps preview and actual creation consistent, including defaults, configuration, raw schema and supported native choice IDs/labels/active/disabled state. Self/avatar/routing fields on choices are excluded. Material timestamps and native field ordering do not alter the fingerprint. Metadata/account reads now have captured-policy checks on both sides of each exchange.

`planning_review::verification::revalidate_ticket_manifest` treats the immutable preview as comparison data and performs complete fresh native review and manifest compilation. It requires the original approvals, revisions, body fingerprints and policy, not replacement approvals. It retains the original observation window and captured policies in a private-field result. Window checks bracket policy reads. Every batch must repeat native observation; `check()` does not itself contact the provider or renew the window. Neither `VerifiedReview` nor `ReviewBinding` is restored from stored JSON. A raw stored-manifest projection supplies comparison data only.

Cross-cutting dispatch and unknown/shared changes still widen scope. Output: `target/reviewed-material-verifier-selftest.log`; selected commands: `target/reviewed-material-verification-plan.json`.

The first matching/replacement/late-check revalidation cases hit an expired artifact-store capability reused across three simulated invocations. The fixture now opens the store for each invocation and final inspection; deadlines were not widened. Earlier failing log: `target/ticket-revalidation-native.log`.
