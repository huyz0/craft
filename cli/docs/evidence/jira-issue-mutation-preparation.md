## Implemented contract

The [preparation contract](../jira-issue-mutation-preparation.md) and cloud-provider scenario specify separate edit and transition intents, numeric issue identity, exact expected issue state, private native metadata, closed field compilation, required-field evidence and frozen operation/principal/freshness binding.

`crates/craft-provider-jira/src/issue_context/mod.rs` retains the unprojected native response and typed issue observation privately, factors the narrow issue-state parser for current-value qualification, and rejects nonempty or malformed native error maps. Public pages, cached context and read schema are unchanged.

`crates/craft-provider-jira/src/issue_context/mutation/{mod,input,fields}.rs` implements strict edit/transition inputs and internal descriptors, native field compilation, ADF text encoding, option-ID qualification, typed label deltas and frozen calls. Edits omit untouched fields, including unsupported required fields. Transitions require expanded screen metadata, exact eligible IDs and expected destination status. Required omissions use a qualified default or one narrow fresh value read under unchanged state. Required-label deltas validate the resulting set without resubmitting unrelated labels. Generic native maps, status substitution, account/hierarchy fields and administrative bypasses are unavailable.

The private frozen object exposes an immutable call and inert before-state/destination metadata. Its final check refuses a changed operation, grant, actor, expired age or backward clock. Preparation checkpoints run after optional current-value observation. Deserializing selected output cannot construct either live metadata or frozen proof. The eventual host still needs explicit access/policy, durable intent/send claim, final checks and complete response/persistence recovery.
