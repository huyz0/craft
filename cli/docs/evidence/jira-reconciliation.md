Date: **10 November 2026**, Australia/Sydney. Internal provider/host qualification only. No public command, real credential provisioning, live tenant mutation, publication or deployment was enabled. Baseline: [action candidates and policy](issue-action-command.md).

## Contract and implementation

The [reconciliation contract](../jira-reconciliation.md), operation-recovery scenario and design define original-request/journal binding, separate recovery authority, read-only investigation and the distinction between current state and effect attribution before implementation.

`crates/craft-provider-jira/src/reconciliation.rs` declares only bounded numeric issue GETs under the read scope. It normalizes exact ID/project/state and assignee identity, keeps 404 absent-or-invisible, sanitizes failures and retains earlier qualified observations on partial failure. `issue_context::parse_state` is now crate-visible for shared state qualification. No returned link, arbitrary query or write route supplies authority.

`crates/craft-cli/src/issue_recovery.rs` reparses the original supported write through the existing create/mutation host preparation and binds the exact descriptor/payload/target/grant/actor to the journal before auth. It never begins, claims, resets or updates an operation record. Create investigations use bounded known/explicit candidates; no identity means explicit unresolved local output without credential acquisition. Existing-issue investigations use only the original numeric issue. Initial submission assessment and job evidence remain independent of observations and overall workflow completion. Complete initial/latest journal, partial observations and independent renewal receipts survive qualified failures. Final access/policy checks precede the last journal comparison, detecting a change caused during final verification without overwriting the competing receipt. Original descriptor declarations and journal schema are unchanged.

Recovery policy is trusted host configuration with explicit project/grant/actor and allowed commands; existing write policies grant none. Persisted recovery administration, typed/public command registration, automatic correlation discovery and job strategies remain unfinished. Public discovery is checked separately below.
