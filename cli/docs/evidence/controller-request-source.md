# Canonical source recovery for reviewed issue creation

11 November 2026, Windows x86_64. Reviewed ticket issue-create steps now retain their exact canonical original before locking credentials for that native step. The deterministic operation ID reported by the controller can be passed to `operation reconcile --saved` under the original Jira profile and separate recovery policy. The controller still stops on unknown outcomes; investigation does not adopt a mapping, upgrade attribution or complete the run.

The shared `PreparedCreate::retain_source` adapter is used by standalone and controller writes. It preflights receipt capacity, captures the immutable original/full native binding through the existing requests store, and preserves native/source uncertainty independently. The controller publishes its step intent first. Capture failures enter normal controller evidence handling without an HTTP outcome or new claim. Later credential-lock/client-preparation failures also retain the confirmed source receipt and reread current journal evidence before returning. No new public command, native descriptor, historical logical binding or review authority was introduced.
