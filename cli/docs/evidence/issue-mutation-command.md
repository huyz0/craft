## Contract and implementation

The [candidate/policy contract](../issue-mutation-command.md) describes typed edit and transition input, pure preflight, normal profile/site resolution, separate per-project mutation authority and captured checks. `craft-runtime/src/issue_mutation_policy.rs` adds explicit installation/profile/grant/project/actor records, enabled state, closed canonical edit/transition operations, per-row revision CAS, apply/preflight administration and a 256-project-per-profile limit. Different projects retain independent revisions. Create and read permissions grant neither mutation operation.

`craft-runtime/src/profiles.rs` migrates schema seven to eight atomically, creating an empty policy table and checking its exact SQL and absence of triggers. Settings and the new mutation-policy payload use format one; existing policy encodings are unchanged. Historical fixtures remove the new table when simulating older versions; expected current-schema assertions now use eight. No migration infers write access or rewrites prior profiles/policies/journal/cursors.

`craft-cli/src/issue_mutation/command.rs` and its tests connect required expected-state/changes objects, bounded JSON flag parsing, explicit operation/apply, exact numeric issue/project context, pure complete output preflight and native credential selection to the existing host. Candidate registration remains separate from startup/catalog registration. Skipped Jira parser variants, command identity/input decoding and a dedicated mutation dispatch preserve the complete host envelope. Agent input and repository hints cannot supply policy or service actor identity.
