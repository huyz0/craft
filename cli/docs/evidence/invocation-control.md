# Invocation output and interruption

Observed on 9 November 2026, Windows x86_64 MSVC, Rust 1.99.1. `craft-runtime` now owns native clock/signal/input-worker infrastructure; pure cancellation/deadline contracts live in `craft-core/src/control.rs`.

Normal commands publish one compact JSON envelope with stable exit categories, bounded errors and no normal prompt/browser/pager. Human help/version retain their documented plain-text exception. JSON reads have an invocation-wide monotonic work budget: 60 seconds by default, `--timeout-ms` from 1 millisecond to one day. A blocked input worker does not prevent the main invocation from observing timeout or Ctrl-C. Thread creation failures become structured errors. The input helper is for a CLI process lifetime, not a general long-lived worker executor.

Runtime tests verify that wall-time changes cannot extend a deadline, cancellation takes priority over expiry, a blocked reader observes both controls, and completed reads remain bounded. Subprocess tests keep stdin open without delivering EOF and observe one `DEADLINE_EXCEEDED` envelope, exit 60 and `not_sent`; closing stdout produces no panic or stderr trace. The CLI checks control before dispatch and preserves a completed result during publication. Hosts that have sent must preserve confirmed/unknown effects instead of using the control's pre-send error state. Mutation transport/journal integration remains separate work.
