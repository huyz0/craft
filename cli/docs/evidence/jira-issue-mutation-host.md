## Implemented behavior

The [host contract](../jira-issue-mutation-host.md) and cloud-provider scenario define exact trusted numeric-project/operation/grant/actor policy, pure input/apply/output preflight, sealed service access and explicit metadata/write scopes, private frozen preparation, one native send claim and operation-specific completion. `crates/craft-cli/src/issue_mutation.rs`, `issue_mutation/host.rs` and their tests implement that composition. Provider `issue_context/mutation/result.rs` interprets documented 204 acknowledgments and operation-specific refusals. Native issue identity alone is never mutation-effect evidence, and matching later values do not authorize attribution or replay.

Dynamic policy is checked before authentication, at every native metadata boundary, before request construction and after the send claim. The original metadata clocks and verified access are checked after claim acquisition. Started/terminal/foreign operation IDs refuse before new auth or metadata work. Independent credential-cache receipts survive resource refusal. A failed claim attempt retains uncertainty and refreshes prior journal evidence when readable; an older prepared record cannot downgrade that uncertainty. Cancellation and final-preflight refusal do not reopen claims.

Completion preserves operation receipts, actual target, step, persistence disposition/revision, bounded HTTP/rate metadata and cache updates under field selection. Confirmed remote effects survive local recording failure or lost acknowledgment. Prior/foreign records and unexpected additional journal steps remain visible; exceptional evidence uses preserving output if it exceeds the normal preflight estimate. Public schema and discovery remain separate from the internal host response schema.

The CLI manifest adds one synthetic-only `jira_issue_mutation_host` target. The gate and isolation checker include all eight composed targets. Dependency inventory comparison found only the CLI manifest hash changed; locked graph, packages and dependency edges are unchanged. No runtime state migration or new production dependency was introduced.
