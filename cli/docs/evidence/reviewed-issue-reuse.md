# Explicit reviewed reuse of existing Jira issues

11 November 2026, Windows x86_64. The existing 67-command development executable now supports a newly reviewed plan explicitly reusing an existing issue with an original create-operation reference. This advances unknown-create and changed-plan recovery through fresh approval and a new run, while old runs remain immutable.

`craft-workflows::plans::JiraMapping` gains optional `existing_issue`, omitted from old serialization and rendering. The visible plan renders/imports an exact paired decision. Validation rejects malformed/excluded or duplicate decisions. Review preparation reads the selected issue through a separate compiled Jira issue-get registry and binds exact identity/project/type and the decision into resolved review material. Ordinary task/create proposals are still qualified.

Application adds a separate `Reuse` step and strict immutable record. It caches the installed native create descriptor digest once per run, checks the exact origin operation/full journal, permits only an uncertain or matching confirmed same-project create with no unexpected step/job, and never updates that journal or obtains a new native create claim for the reused task. `StepSpec.origin_operation_id` is omitted for old native steps. Reuse evidence and unresolved original attribution remain separate from new workflow completion. Progress/results and the result page expose reused identities. Origin drift on resume retains both the earlier mapping and latest original record; generic native fallback cannot erase that conflict.
