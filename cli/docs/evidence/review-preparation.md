# Live review preparation

Date: 10 November 2026. `review prepare` now imports the current shared plan and referenced designs, qualifies explicit per-task Jira create proposals through native metadata and records immutable local human-review context. It does not submit a Jira write, claim a journal send, publish a comment, verify approval or create tickets.

The workflow requires an explicit Confluence service profile, enabled reviewer policy for the exact space, page-read policy with the same grant/actor, and configured project create-preparation policies for every task proposal. Native locks and sealed access retain credential authority. The new Confluence workflow callback adds checks to the existing policy check; it cannot replace that check. The Jira path reuses the read phase of existing create preparation and records frozen payload data without submitting it.

The artifact retains raw storage bodies, imported plan/design documents, native revisions, exact proposed inputs/payloads, material metadata and the compact approval statement. Included task identities/titles, project keys and issue-type names must match; design references bind native versions and semantic document digests. The portable material digest excludes observation time and local credential/profile identities, sorts field rows and includes reported defaults. Omitted fields with unreported defaults refuse preparation. Snapshots/artifacts are bounded to 32 MiB, native acquisitions to 1,024, and the envelope reserves 1 MiB for complete multi-profile effects while returning compact data.
