# Saved canonical sources for standalone issue recovery

11 November 2026, Windows x86_64. Standalone issue create/update/assign/unassign/delete and transition apply now retain an immutable private canonical source before native acquisition/sending. `operation reconcile --saved` loads it by operation ID. This does not add replay, effect attribution, current permission or live tenant qualification.

`saved_requests.rs` stores a strict format-one binding/original document in the existing owned artifact implementation under the selected state's requests root. Names derive from the operation ID digest; source size is bounded to 2 MiB to accommodate the existing 1 MiB input plus metadata. Load validates artifact metadata and recomputes the original native binding. Same-binding reuse preserves the first source and output selection; changed logical intent refuses without replacement. Started/foreign journals do not acquire a new source. Publication failure rereads journal evidence, preserving concurrent unknown records and conservative unreadable-state flags.

Create and mutation public adapters wrap native data with a compact `saved_request` name/digest/publication-state receipt. A 512-byte reserve covers that bounded field. Source-only projections retain native mandatory evidence and do not leak into native input. Public root and `execute_saved` preflight the source reserve; internal preparation and `execute_cached` keep their prior native budgets/results. Native schemas/descriptors and original-binding preparation remain unchanged, preserving historical journal digests and internal ticket-controller contracts.

Saved selection is exclusive with an explicit original. Its IDs/candidates/fields/budget are validated before state, then source loading re-enters ordinary current profile, recovery policy and journal-binding checks. Legacy/controller requests without a source remain explicit gaps; explicit-original investigation is preserved. No source is a grant, lease, approval or replay token.
