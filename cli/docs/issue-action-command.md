# Issue action candidates and policy

The public mutation adapters include `jira issue assign`, `jira issue unassign` and `jira issue delete`. Their native behavior follows [issue actions](jira-issue-actions.md). See [current usage](jira-issue-writes.md) and [independent activation review/evidence](evidence/jira-issue-action-activation.md). Live qualification remains separate.

Assignment requires `operation_id`, apply, numeric issue ID, complete expected issue state, explicit `expected_assignee` and destination `account_id`. Unassignment requires the same inputs without a destination. Deletion requires operation/apply/issue/state plus explicit `subtasks`. Flags accept bounded JSON objects for expected state, expected assignee and subtask mode. Structured input requires the same fields and rejects null, unknown members and duplicate JSON. Missing flags remain absent until validation; neither an unassigned expectation nor refuse/cascade mode is synthesized. Validate all local input, projection and complete receipt capacity before opening state or credentials.

Reuse exact profile/site resolution and the expected numeric project's trusted mutation record. `Assign`, `Unassign`, `Delete` and `DeleteAllSubtasks` are independent allowances appended after edit and transition. Both deletion allowances map to the same native command; the typed subtask mode selects the exact required allowance. Enabling ordinary deletion does not enable cascade, and enabling assignment does not enable unassignment. Native permissions remain independent.

Keep SQLite schema eight and the existing table. Read format-one records only with their original edit/transition operation set. A format-one payload containing any newly recognized action string remains invalid, even though that string is valid in format two. Preserve valid old records byte-for-byte on read, with no inferred permissions or automatic rewrite. Trusted setters write format two under existing apply, receipt preflight and row-revision CAS. Only an explicit trusted update can upgrade a row. Failed preflight, revision conflict or pre-commit cancellation leaves the old payload untouched. A lost/failed commit acknowledgment retains local-write uncertainty and requires inspecting the exact project row before retrying; it is not proof of rollback. Format two supports a canonical unique nonempty list drawn from all six allowances. Unknown formats/operations and malformed, duplicate, unsorted, foreign or mismatched rows remain refused without repair. Older binaries refuse format-two rows; no downgrade is attempted.

Capture the entire policy row, including format, revision, actor, grant, target and allowance list. Recheck it before auth, each native-read boundary, preparation and the final claimed send after frozen verification. Missing/disabled/excluded authority denies; any other captured change conflicts. A pre-send refusal sends no resource mutation; once a send claim exists, preserve conservative uncertainty and independent cache receipts. Reuse existing completion and no-replay semantics. Mutation dispatch preserves the exact decoded intent, original request ID, receipt, prior journal evidence and output policy.
